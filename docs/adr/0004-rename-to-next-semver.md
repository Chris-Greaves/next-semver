# Script and Action renamed from `get-semver` to `next-semver`

The name `get-semver` implied the script retrieves an existing version — a tag, a version file, or similar — when its actual behavior is to *compute* a version that hasn't been tagged yet, by scanning commits since the last Release Tag and applying Conventional Commits bump rules. We decided to rename the script, the composite Action, and the npm package from `get-semver`/`get-semver.sh` to `next-semver`/`next-semver.sh`, so the name itself states that the output is a proposed next version, not a lookup of a current one. This was chosen over keeping `get-semver` and disambiguating only in prose (README, `--help` text, etc.), because a name that already states the tool's behavior needs no further explanation for a `uses: <owner>/next-semver@v1` reference or a `./next-semver.sh` invocation to be self-explanatory. `.scratch/` issue and spec files that predate the rename keep the `get-semver` name, since they're a historical record of what was built under that name at the time.
